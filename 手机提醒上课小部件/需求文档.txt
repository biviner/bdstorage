# 智能课表桌面小组件 — 产品需求文档（PRD V1.0）

**项目名称：** 智能课表（暂定）

**产品类型：** 手机应用 + 系统桌面小组件（Widget）

**目标平台：** iOS / Android（待确定首发平台）

**产品阶段：** MVP 第一版需求设计

**版本：** V1.0

---

## 一、产品概述

### 1.1 产品定位

一款面向学生的智能课表工具，支持通过课表截图或照片快速导入课程信息，在手机桌面小组件中直观展示当天课程、当前课程和下一节课程，并通过系统通知提醒用户按时上课。

### 1.2 核心目标

1. **快速导入：** 无需逐门手动录入，通过图片识别生成课程表。
2. **方便查看：** 无需打开应用，在手机桌面即可看到课程安排。
3. **及时提醒：** 根据课程时间自动发送上课提醒，减少迟到或忘记上课的情况。
4. **轻量易用：** 界面简洁，减少不必要的操作步骤。

### 1.3 目标用户

- 大学生、研究生。
- 课表相对固定、每周循环的学生。
- 需要桌面查看课程并接收提醒的用户。

## 二、核心功能需求

### 2.1 图片导入课表

**优先级：P0（必须实现）**

用户可以选择手机相册中的课程表截图或照片。

**功能要求：**

- 支持 JPG、PNG、HEIC 等常见图片格式（具体取决于平台）。
- 支持单张及多张图片导入。
- 自动识别课程名称、星期、节次或时间段、教室、教师、上课周次。
- 尽可能识别合并单元格、跨节课程、单双周及指定周次。
- 识别完成后生成可编辑的课表预览。
- 对识别不完整或有歧义的字段作出提示，不直接猜测关键信息。
- 用户确认后正式保存课表。

**基本操作流程：**

上传图片 → 自动识别 → 展示识别结果 → 手动修正 → 确认导入。

**特殊情况：**

- 图片模糊：提示重新上传。
- 无法识别节次时间：要求用户设置学校作息时间。
- 存在课程冲突：保留课程并提示用户检查。
- 同一课程跨多周：按照课程周次生成循环安排。

### 2.2 课程表管理

**优先级：P0**

支持周课表及课程详情管理。

**主要功能：**

- 按周一至周日展示课程。
- 支持查看上一周、下一周。
- 支持设置学期开始日期、总周数。
- 支持按每周、单周、双周、指定周次重复课程。
- 支持新增、修改、删除课程。
- 支持修改课程时间、地点和名称。
- 支持手动设置停课日期或临时调课。
- 课程修改后同步更新桌面小组件与提醒计划。

**单门课程的数据字段：**

| 字段 | 是否必需 |
|---|---|
| 课程名称 | 必需 |
| 星期 | 必需 |
| 开始时间、结束时间 | 必需 |
| 上课周次 | 必需 |
| 教室/地点 | 可选 |
| 教师 | 可选 |
| 课程颜色 | 可选 |
| 备注 | 可选 |
| 提醒时间 | 可选 |

### 2.3 桌面课表小组件

**优先级：P0**

这是产品的核心功能。

支持系统桌面小组件，用户可以将其添加到手机主屏幕。

**小组件类型：**

**A. 小尺寸：下一节课**

- 展示下一节课程名称。
- 展示上课时间、地点。
- 展示距离上课还有多久（以系统支持的刷新方式实现）。
- 当前无课时展示简洁的空闲状态。

**B. 中尺寸：今日课程**

- 展示当天日期、星期。
- 按时间顺序列出当天课程。
- 区分已结束、正在进行、尚未开始的课程。
- 突出下一节课程。
- 点击进入完整课表或课程详情。

**C. 大尺寸：周课表**

- 展示本周的主要课程安排。
- 标记当前日期。
- 通过颜色区分课程。
- 支持查看当前教学周。

**显示原则：**

1. 课程信息清晰易读。
2. 尽量减少文字拥挤。
3. 支持浅色、深色模式。
4. 小组件随日期与课程安排变化自动更新。
5. 不依赖持续打开主应用。

**技术注意：** iOS 和 Android 的小组件刷新机制不同，尤其是实时倒计时、分钟级更新等功能存在系统限制。第一版优先保证课程信息和状态正确，不将每秒刷新作为必须实现的功能。

### 2.4 上课提醒

**优先级：P0**

通过手机系统通知提醒用户上课。提醒由应用负责调度，不依赖用户打开小组件。

**默认提醒规则：**

- 每节课开始前 15 分钟通知一次。
- 支持关闭提醒。
- 支持修改默认提前时间。
- 支持为单门课程独立设置提醒。

**可选提醒时间：**

- 准点提醒
- 提前 5 分钟
- 提前 10 分钟
- 提前 15 分钟（默认）
- 提前 30 分钟
- 自定义提前时间

**通知内容示例：**

标题：15 分钟后上课

内容：数据结构｜08:30 开始｜教学楼 A203

**补充规则：**

- 非上课周次不发送提醒。
- 停课、调课后重新调整提醒。
- 已经过去的课程不补发过期提醒。
- 通知被关闭时提示用户开启系统通知权限。
- 根据系统能力安排本地通知，并考虑系统可能限制通知时间精度。
- 提醒不依赖云端推送服务。

### 2.5 课程时间设置

**优先级：P0**

由于不同学校的上课时间不同，需要支持两种课程时间模式。

**模式 A：节次模式**

例如：

- 第 1–2 节：08:00–09:40
- 第 3–4 节：10:00–11:40

用户可以先配置一套学校作息时间，识别出的节次自动匹配对应时间。

**模式 B：具体时间模式**

直接填写课程开始和结束时间，不依赖学校节次。

用户可修改默认作息时间。

## 三、页面设计需求

### 3.1 主应用页面

| 页面 | 主要内容 |
|---|---|
| 首页 | 今日课程、下一节课程、完整周课表入口 |
| 周课表 | 周一至周日课程网格、周次切换 |
| 图片导入 | 上传图片、查看识别进度 |
| 导入确认 | 检查并修正识别结果 |
| 课程详情 | 查看及编辑课程信息 |
| 设置 | 学期、作息时间、提醒、外观等 |

### 3.2 桌面小组件设计原则

- 以课程名称和时间为最重要信息。
- 使用不同颜色标记课程，但不过度装饰。
- 正在进行的课程优先突出。
- 今日无课时提供明确提示。
- 不同尺寸应分别优化布局，而不是简单缩放。
- 小组件内容与主应用保持一致。

---

## 四、关键业务规则

### 4.1 周次计算

以学期开始日期为基准计算教学周。

- 支持设置学期第 1 周的起始日期。
- 支持单双周。
- 支持第 1–16 周等连续周次。
- 支持不连续周次，例如第 1–8、10–16 周。
- 超出课程有效周次时，不再展示为当天课程，也不发送提醒。

### 4.2 课程状态

课程主要分为三种状态：

1. 未开始：当前时间早于课程开始时间。
2. 进行中：当前时间位于课程开始和结束时间之间。
3. 已结束：当前时间晚于课程结束时间。

课程冲突时允许同时保存，并提示用户处理。

### 4.3 数据保存

第一版采用本地存储优先策略：

- 课表保存在用户手机中。
- 无网络时仍可查看课表。
- 无网络时仍可使用已安排的本地上课提醒。
- 修改课程后需要重新计算受影响的通知。
- 图片识别如使用云端服务，应明确告知用户图片会被上传处理。

## 五、用户操作流程

### 5.1 首次使用

安装应用 → 进入欢迎页 → 选择导入课表 → 上传图片 → 识别 → 设置学期与节次时间 → 确认课表 → 授权通知 → 引导添加桌面小组件 → 完成。

### 5.2 日常使用

用户解锁手机 → 查看桌面小组件 → 了解当前或下一节课程 → 接收上课提醒 → 必要时点击小组件查看详情。

### 5.3 修改课表

打开主应用 → 选择课程 → 修改时间、地点或周次 → 保存 → 自动更新小组件显示和相关提醒。

## 七、非功能性要求

**性能：** 已保存的课表应能够快速打开，桌面组件不应频繁消耗设备电量。

**稳定性：** 应用退出或手机重启后，课表数据保留，提醒按系统允许的方式继续有效。

**隐私：** 默认不要求账号注册；仅申请必要的相册、通知等权限，避免收集不必要的个人信息。

**可用性：** 用户在导入后应能清楚判断识别是否正确，避免错误时间导致漏课。

**兼容性：** 具体最低系统版本与桌面小组件能力在首发平台确定后明确。

---

## 八、MVP 验收标准

1. 用户可以从手机相册选择课表图片并发起识别。
2. 用户可以检查、修改并保存识别后的课程信息。
3. 能够正确处理普通周课表、单双周和指定周次课程。
4. 小组件能够显示当天课程及下一节课。
5. 用户可以配置提前提醒，系统按有效课程计划安排通知。
6. 修改、删除、停用课程后，相关课程显示及未来提醒同步调整。
7. 手机无网络时，已保存课表仍可以查看。
8. 导入失败、识别不确定、缺少通知权限等情况均有明确提示。

---

## 九、待确认的关键产品决策

正式进入 UI 设计与技术开发前，需要确定：

- 首发平台：Android 。
- 小组件的核心形式：下一节课、今日课程或完整周课表。
- 课表图片来源：大学教务系统截图为主，还是各种自制课表图片。
- 图片识别方式：设备本地识别、云端 AI 识别或混合方案。
- 是否必须支持复杂的单双周、跨周、调课情况。
- 是否提供课程开始前的多个提醒。
- 第一版是否完全不需要账号与服务器。

**产品原则：第一版优先保证“识别正确、展示清晰、提醒可靠”，不为了增加功能而增加使用复杂度。**
