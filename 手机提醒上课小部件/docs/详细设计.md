## 3. 数据库详细设计（Room schema v1，B2）

### 3.1 表定义（DDL 语义，实体注解实现）

```sql
CREATE TABLE semester_setting (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  first_week_start_date TEXT NOT NULL,        -- ISO yyyy-MM-dd，第1周周一
  total_weeks INTEGER NOT NULL DEFAULT 20,
  default_reminder_lead_minutes INTEGER NOT NULL DEFAULT 15,
  timetable_mode TEXT NOT NULL DEFAULT 'PERIOD'   -- PERIOD | EXACT_TIME
);

CREATE TABLE period_time (
  period_index INTEGER PRIMARY KEY,           -- 1..15
  start_time TEXT NOT NULL,                   -- HH:mm
  end_time TEXT NOT NULL
);
-- 预置默认作息（首次启动 seed）：1-2节08:00-09:40, 3-4节10:00-11:40,
-- 5-6节14:00-15:40, 7-8节16:00-17:40, 9-10节19:00-20:40（连续节次合并为行）

CREATE TABLE course (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  day_of_week INTEGER NOT NULL CHECK (day_of_week BETWEEN 1 AND 7),   -- 1=周一
  start_minute INTEGER NOT NULL CHECK (start_minute BETWEEN 0 AND 1439),
  end_minute   INTEGER NOT NULL CHECK (end_minute BETWEEN 1 AND 1440),
  location TEXT, teacher TEXT, color_argb INTEGER, note TEXT,
  week_pattern TEXT NOT NULL DEFAULT 'ALL',   -- ALL | ODD | EVEN | CUSTOM
  custom_weeks TEXT,                          -- "1-8,10,12-16"，仅 CUSTOM 时非空
  reminder_enabled INTEGER NOT NULL DEFAULT 1,
  reminder_lead_minutes INTEGER,              -- NULL=跟随全局默认
  paused_dates TEXT,                          -- "2026-11-20,2026-11-27"，NULL=无停课
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE INDEX idx_course_day ON course(day_of_week);

CREATE TABLE recognition_draft (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at TEXT NOT NULL,
  raw_image_uri TEXT,
  courses_json TEXT NOT NULL                  -- RecognizedCourse 列表序列化
);
```

校验注解：DAO 层不重复校验合法区间，实体字段用 `@Check` 语义在 schema 层兜底；非法输入在 ViewModel 层先行拦截并提示。

### 3.2 customWeeks 编解码（B2，纯函数进 domain）

- 编码：`List<Int> → "1-8,10,12-16"`（连续≥2 合并为区间，升序去重）。
- 解码：字符串 → `Set<Int>`；容错：空段、逆序、重复均容忍并归一化；非法 token 丢弃并在返回值附 warning 列表。
- 单测必须覆盖：`1-8,10,12-16` / `单周`以外的混排 / 空串 / `16-1` 逆序段 / 超界（>totalWeeks 保留但由 WeekCalculator 过滤）。

### 3.3 DAO 接口（B2）

```kotlin
@Dao interface CourseDao {
  @Query("SELECT * FROM course ORDER BY day_of_week, start_minute") fun observeAll(): Flow<List<Course>>
  @Query("SELECT * FROM course WHERE day_of_week = :day ORDER BY start_minute") suspend fun byDay(day: Int): List<Course>
  @Query("SELECT * FROM course WHERE id = :id") suspend fun byId(id: Long): Course?
  @Insert suspend fun insertAll(courses: List<Course>): List<Long>
  @Update suspend fun update(course: Course)
  @Delete suspend fun delete(course: Course)
  @Query("UPDATE course SET paused_dates = :dates WHERE id = :id") suspend fun setPaused(id: Long, dates: String?)
}
```

SemesterSettingDao / PeriodTimeDao 同构（单行 upsert / 批量 upsert）。

### 3.4 写后钩子（B2）

Repository 门面（`TimetableRepository`）每个写方法（insert/update/delete/setPaused/学期设置变更/作息变更）执行后必须依序回调：

1. `ReminderScheduler.rescheduleAll()`
2. `WidgetUpdater.refreshAll()`

通过构造注入的 `ChangeNotifier` 接口实现，app 模块装配时绑定；`core/data` 不直接依赖 scheduler/widget 模块（依赖倒置，保住模块边界）。

## 4. 领域层算法详设（B1）

### 4.1 WeekCalculator

```kotlin
object WeekCalculator {
  /** 学期第几周；firstWeekStart 为第1周周一。today 若早于它或超过 totalWeeks → null。
   * 周一为一周起点：week = ((today - firstWeekStart).days / 7) + 1 */
  fun currentWeek(firstWeekStart: LocalDate, today: LocalDate, totalWeeks: Int): Int?
  fun dayOfWeekOf(firstWeekStart: LocalDate, date: LocalDate): Int  // 1..7
}
```

边界用例（单测表）：today=firstWeekStart→1；today 为首周周日→1；today=第二周周一→2；today 早于起点→null；today 恰好=起点+totalWeeks*7 天→null（学期结束次日）。

### 4.2 WeekPattern 匹配

```kotlin
enum class WeekPattern { ALL, ODD, EVEN, CUSTOM;
  fun matches(week: Int, custom: Set<Int>): Boolean = when(this) {
    ALL -> true; ODD -> week % 2 == 1; EVEN -> week % 2 == 0; CUSTOM -> week in custom } }
```

课程级入口 `courseActiveInWeek(course, week)`：week 为 null（学期外）→ false；再查 `pausedDates` 是否含本周对应日期（见 4.4）。

### 4.3 CourseStatusResolver

输入课程起止分钟与当前分钟：`now < start → NotStarted`；`start ≤ now ≤ end → Ongoing`；`now > end → Ended`。边界：now==start 算进行中，now==end 算进行中（含下课铃当分钟），now==end+1 算已结束。

### 4.4 ReminderPlanner

```kotlin
data class PlannedReminder(val courseId: Long, val triggerAt: LocalDateTime,
                           val title: String, val body: String)

object ReminderPlanner {
  /** 窗口：now ..< now+7d。逐课逐日扫描：
   *  1) 该日期的教学周 w（WeekCalculator）
   *  2) courseActiveInWeek 且该日期不在 pausedDates
   *  3) triggerAt = 日期 + 课程开始时间 - lead（lead=course.reminderLeadMinutes ?: 全局默认，≤0 表示准点）
   *  4) triggerAt > now 才收（过期不补发）
   *  输出按 triggerAt 升序 */
  fun plan(courses, settings, timetable: List<PeriodTime>?, now: LocalDateTime): List<PlannedReminder>
}
```

文案：title = `"${lead}分钟后上课"`（lead=0 时 `"现在上课"`）；body = `"$name｜${HH:mm} 开始${location 非 null 则 "｜$location"}"`。与 PRD 2.4 示例一致。

单测必须覆盖：单双周过滤 / CUSTOM 不连续周 / pausedDates 当日不发 / lead 跨午夜（lead > 当日凌晨差值则落在昨日，仍须设置——用 AlarmManager 允许过去 0 秒内场景不存在，因窗口过滤已保证未来时刻）/ 课程在窗口边界 / 全局与单课 lead 叠加优先级。

### 4.5 PeriodMapper

`periodsToMinutes(periodStart, periodEnd, timetable)`：查表返回 (startMinute, endMinute)；节次缺失（如无第 11 节）→ null，调用方提示「节次超出作息表，请到设置页补全作息时间」。

### 4.6 ConflictDetector

`conflictsOf(courses): List<Pair<Long, Long>>`：同 day_of_week 且区间重叠（`a.start < b.end && b.start < a.end`，相接不算冲突）。确认页与周课表页调用，UI 层高亮但不阻止保存。

### 4.7 WidgetText

- 2×2 空闲文案：今日无课 → `"今天没有课"`；今日课全结束 → `"今天课程已结束"`；有下一节 → 见 4.4 文案复用 + `"距上课还有 X 分钟"`（<1h 显示 `X 分钟`，≥1h 显示 `X 小时 Y 分`）。
- 全部为纯函数，输入 (courses, now, settings) 输出不可变文案模型，小组件与首页直接消费。

## 5. 识别网关详设（B3）

### 5.1 接口与实现

```kotlin
interface ScheduleRecognizer {
  suspend fun recognize(imageJpeg: ByteArray): Result<List<RecognizedCourse>>
}
data class RecognizedCourse(
  val name: String?, val dayOfWeek: Int?, val periodStart: Int?, val periodEnd: Int?,
  val startTime: String?, val endTime: String?,     // "HH:mm"，节次缺失时模型直接给时间
  val weeksRaw: String?, val weeksParsed: List<Int>,
  val location: String?, val teacher: String?, val confidence: Double
)
```

`OpenAiVisionRecognizer`（首期唯一实现）：POST `{baseUrl}/chat/completions`，`messages` 含 image_url(base64 data URI) + 系统 prompt（见 5.3），`response_format={"type":"json_object"}`，temperature 0。超时 60s，重试 1 次（仅网络错误，非 4xx）。

### 5.2 响应校验规则（B3）

1. JSON 解析失败 → `Result.failure(RecognitionFailed)`，文案「识别服务返回异常，请重试」。
2. 逐字段清洗：dayOfWeek 钳到 1..7（「周一」/「星期一」/`Mon` 等中文映射在 prompt 约定+代码兜底）；confidence < 0.6 或关键字段（name/dayOfWeek/时间）缺失 → 该课 `lowConfidence=true`，确认页标黄；confidence < 0.3 或 name 缺失 → 该课丢弃并计数，完成后提示「N 条疑似课程信息不完整已忽略，可手动添加」。
3. `periodStart/End` 非空时经 PeriodMapper 映射为分钟（映射失败 → 该行标黄提示补作息）；否则用 startTime/endTime。
4. weeksParsed 与 weeksRaw 冲突（原文含「单」而 parsed 奇偶不符等）→ 整行标黄，保留两者供用户对照修正。

### 5.3 识别 prompt（v1 定稿，入库 `core/network/assets/prompt.md`）

系统 prompt 要点（完整文本实现时按此逐条落实）：

- 角色：你是课表截图解析器，只输出 JSON，不解释。
- 输出 schema：`{"courses":[{name, dayOfWeek(1-7,周一=1), periodStart, periodEnd, startTime("HH:mm"|null), endTime, weeks("原文"), weeksParsed([int]), location, teacher, confidence(0-1)}]}`。
- 规则：合并单元格拆为多行并各自标注周次；跨节连堂合并为一行（periodStart=首节, periodEnd=末节）；单双周列/括号注记写入 weeksRaw 并解析为 weeksParsed；表格线不清晰时按对齐推断，confidence 如实给出 ≤0.5；看不清的字段填 null，禁止编造。
- 用户消息：图片 + 一句「请解析这张课表截图」。

### 5.4 导入页状态机（B3）

```
Idle → Picking(选图) → Uploading → Recognizing → Done(draftId) | Failed(msg 可重试)
```

- Uploading 前弹「图片将上传至你配置的识别服务（{baseUrl}），确认继续？」，一次性记住选择。
- App 被杀 → 状态作废，重进重选图（概要 §8 已定，不做任务恢复）。
- 识别服务未配置（无 key）→ 入口置灰 + 「请先在设置页配置识别服务」。

### 5.5 确认页交互（B3）

- 行内编辑：name/location/teacher 直接改；dayOfWeek 下拉；时间用节次或时刻二选一（跟随 timetableMode，可单行切换）；weeks 用「周次选择器」网格（1..totalWeeks 点选 + All/Odd/Even 快捷钮），写入 customWeeks。
- 顶部汇总：`识别到 N 门课，M 门需检查（标黄）`；冲突行右侧红色 ⚠ 点击定位到 ConflictDetector 结果。
- 「确认导入」→ 二次确认弹窗列出将写入的条数 → insertAll 事务 → ChangeNotifier → 跳转周课表并 Toast「已导入 N 门课程」。
- 全部丢弃 → 删除草稿，不写库。

## 6. 提醒调度详设（B4）

### 6.1 调度器契约

```kotlin
interface ReminderScheduler {
  /** 幂等全量重排：cancelAll → plan(未来7天) → 逐条 setExactAndAllowWhileIdle */
  suspend fun rescheduleAll()
}
```

- PendingIntent requestCode = `courseId.hashCode()` 与 triggerAt epochMinute 组合 hash，确保同课不同时刻可共存。
- 通知渠道 `class_reminder`（IMPORTANCE_HIGH，B4 建立于 Application.onCreate）。
- AlarmReceiver：取载荷 courseId+triggerAt → 重查该课（已删除/已停课则静默跳过——防陈旧闹钟）→ NotificationHelper.notify() → 立即调用 rescheduleAll()（滚动补排后续 7 天）。
- BootReceiver：BOOT_COMPLETED → rescheduleAll()。
- WorkManager：`ScheduleGuardWorker` 每日 04:00 + 每次 Repository 变更时入队（ExistingWorkPolicy.REPLACE），执行体 = rescheduleAll()。兜底场景：精确闹钟权限被回收、闹钟被 ROM 清除。

### 6.2 权限与引导（B4）

- `SCHEDULE_EXACT_ALARM`（API 31+）在清单声明；设置页显示 `alarmManager.canScheduleExactAlarms()` 状态，false 时黄色提示条 + 跳系统设置按钮。
- `POST_NOTIFICATIONS`（API 33+）首次进入首页时请求；拒绝后首页顶部提示条，可再次发起。
- 国产 ROM 电池白名单：设置页「提醒可靠性」入口展示指引文案（静态说明 + 跳转电池优化设置 intent）。

### 6.3 通知细节

- SmallIcon 用 app 图标；contentIntent → 首页；同课同时刻只发一次（requestCode 去重天然保证）。
- 不做深链到具体课程页（扩展）。

## 7. 小组件详设（B4）

### 7.1 2×2 NextClassWidget

- 内容：状态徽标（未开始/进行中）+ 课程名（最多 2 行省略）+ `HH:mm`（进行中显示 `结束于 HH:mm`）+ 教室（单行省略）+ 倒计时行。
- 计算：取今日课程（dayOfWeek=今天、activeWeek、非停课）→ 当前进行中的优先 → 否则今日最早未开始的 → 都无 → 空闲态文案（4.7）。
- 点击 → 打开该课程详情页（无课 → 首页）。

### 7.2 4×2 TodayWidget

- 头部：`M月d日 周X · 第N周`（学期外显示 `假期中`）。
- 列表：最多展示 5 条，按开始时间排序；每条 = 色块(课程色，缺省取按 name hash 的调色板 8 色) + 名称 + 时间段 + 教室；进行中加粗+`进行中`徽标，已结束 50% 透明度；下一节（第一个未开始的）左侧高亮竖条。
- 底部：今日无课 → 居中 `"今天没有课，好好休息"`。
- 点击 → 首页。

### 7.3 更新机制

- `WidgetUpdater.refreshAll()`：`GlanceAppWidgetManager.updateAll`，执行在 Dispatchers.Default。
- 触发源注册（见概要 §6.3）：`WidgetRefreshWorker` 每 15 分钟（WorkManager PeriodicWorkRequest，flex 5min）+ 午夜 Alarm（AlarmManager.setExact，type RTC）+ ChangeNotifier 回调 + `TIME_SET/TIMEZONE_CHANGED` 广播接收。
- 数据读取一律现查 Repository，不缓存。

## 8. UI 页面详设（B2 主结构，B3/B4 补充）

### 8.1 导航与骨架

单 Activity `MainActivity`，NavHost 路由：`home` / `week/{weekNo}` / `import` / `confirm/{draftId}` / `courseEdit?courseId=` / `settings`。顶栏返回箭头统一；主题 Material3 动态取色 + 浅深色跟随系统。

### 8.2 首页（B2）

- 「下一节课」大卡片：课程名/时间/教室/倒计时（复用 WidgetText）。
- 今日时间线列表（同 4×2 布局规则，条数不限）。
- 空态：无任何课程 → 中央按钮「导入课表」；有课但今日无课 → 「今天没有课」+ 周课表入口。
- 顶部条件提示条：通知权限未授 / 精确闹钟未授权 / 学期未设置（三者按优先级同时只显示一条）。

### 8.3 周课表（B2）

- 网格：左列时间轴（节次模式下按 PeriodTime 渲染行，EXACT_TIME 模式按 1h 刻度），周一~周日列。
- 课程块：颜色 + 名称（2 行截断）+ 教室；冲突块显示 ⚠；点击 → 详情页。
- 顶栏：`第 N 周 ▾` 周切换（±1 周 + 下拉跳转）；当前周高亮「本周」角标；今日列头高亮。
- 学期外：显示 `假期中`，可自由浏览周次。

### 8.4 课程编辑（B2）

- 字段：名称（必填，空则保存钮禁用）、星期、时间模式（节次选择器 | 时刻选择器，随全局模式默认）、周次（同 5.5 选择器）、教室/教师/备注（可选）、颜色（8 色调色板+自动）、提醒（开关 + lead 下拉：准点/5/10/15/30/自定义分钟）、停课日期（多选日期表，展示为 chips 可删）。
- 保存校验：end>start；节次模式查表失败即提示；冲突时弹「与 {课程名} 时间冲突，仍要保存？」。
- 删除：确认弹窗（文案含课程名），删除后 ChangeNotifier。

### 8.5 设置（B2 基础，B3 补识别配置）

- 学期：起始日期选择器（默认下周周一）、总周数（10-30 步进）。
- 作息：节次时刻表编辑（每行节次号+起止时刻；增删行；恢复默认按钮）。
- 提醒：默认提前量下拉（与 8.4 一致）。
- 识别服务（B3）：baseUrl / apiKey（输入框密码型，存储 DataStore，界面打码）/ 模型名 / 「发送测试请求」按钮（成功显示模型返回的原始 JSON 摘要）。
- 关于：版本号、开源许可、图片上传隐私声明全文入口。

### 8.6 DataStore keys（B2）

`uploadConsentAcked:Boolean`；`activeWeekOverride:Int?`（周课表手动翻页记忆，仅 UI 态，重启失效）；识别配置三项（B3）。其余状态一律 Room 或内存。

## 9. 全局约束清单（实现与验收逐条核对）

1. `core/domain` 无 Android import（编译期强制）。
2. 所有课程写路径必经 `TimetableRepository`，写后必触发 ChangeNotifier（防「改了课提醒不变」缺陷）。
3. 提醒重排幂等：任意次连续 rescheduleAll 结果一致（同 requestCode 集合）。
4. 过期提醒永不补发；学期外/停课日/无效周次课程不进计划与小组件。
5. 识别失败/未配置绝不静默降级为手动录入引导以外的东西——不写入任何半成品课程。
6. API key 不进日志；Retrofit 日志拦截器 redact Authorization 头。
7. 周一=1、周日=7 全局唯一约定；一日分钟数 0..1439，跨零点课程不支持（截图课表无此场景，周课表语义内不存在）。
8. Room schema 导出 JSON 入 git；后续迁移必须带 Migration 测试。
