## 一、总体架构

```
┌─────────────────────────────────────────────────┐
│  UI 层（Jetpack Compose）                        │
│  首页 / 周课表 / 图片导入 / 导入确认 / 课程详情 / 设置 │
├─────────────────────────────────────────────────┤
│  ViewModel 层（StateFlow + 协程）                 │
├─────────────────────────────────────────────────┤
│  领域层（纯 Kotlin，可单测）                       │
│  WeekCalculator 教学周/单双周计算                  │
│  CourseStatusResolver 课程状态（未开始/进行中/已结束）│
│  ReminderPlanner 提醒计划计算                     │
├─────────────────────────────────────────────────┤
│  数据层                                          │
│  Room 数据库（课表/课程/学期设置）+ DataStore（偏好）│
│  识别网关 Retrofit（视觉大模型 API，可配 key）       │
├─────────────────────────────────────────────────┤
│  系统集成层                                       │
│  Glance 小组件（2×2 下一节 / 4×2 今日课程）         │
│  AlarmManager+WorkManager 提醒调度（本地，无云推送） │
│  WorkManager 小组件定时刷新                       │
└─────────────────────────────────────────────────┘
```

**关键设计决策：**

1. **领域逻辑纯 Kotlin 化**：周次计算、课程状态、提醒计划全部写成无 Android 依赖的纯函数，JUnit 单测覆盖（这是验收的核心抓手，不信任子员工自报）。
2. **本地优先**：课表数据全部存 Room；无网络可查看课表、可触发已计划的提醒（AlarmManager 离线可用）。仅图片识别走网络。
3. **提醒链路**：`ReminderPlanner` 计算未来 N 天提醒时刻 → `AlarmManager.setExactAndAllowWhileIdle`（声明 `SCHEDULE_EXACT_ALARM` 并引导用户授权）+ `WorkManager` 兜底重排 → `BroadcastReceiver` 发通知。课程增删改后全量重排受影响提醒。
4. **识别协议**：识别服务抽象为 `ScheduleRecognizer` 接口，默认实现调用视觉大模型（OpenAI 兼容协议，用户在设置页填 base_url + api_key + model），返回结构化 JSON（课程名/星期/节次或时间/教室/教师/周次）。识别置信度低的字段在确认页标黄提示，不猜测关键字段。
5. **小组件刷新**：Glance 小组件由 WorkManager 每 15 分钟 + 日切（午夜 Alarm）触发更新；「距上课还有 X 分钟」按系统允许的粒度刷新，不做秒级倒计时（PRD 已豁免）。

## 三、分批落地计划（依赖顺序）

### 批次 0：环境准备（总控本机执行）
- 安装 JDK 17（Temurin）+ Android SDK 命令行工具（platform-tools、platforms;android-35、build-tools）
- 配置 ANDROID_HOME，`gradle wrapper` 可用
- 交付物：`java -version`、`sdkmanager --list_installed` 真实输出

### 批次 1：项目骨架 + 领域层（纯逻辑，可全量单测）
- Gradle 项目骨架（Kotlin 2.x + Compose BOM + Room + Glance + WorkManager + Retrofit），空 App 可 `assembleDebug` 出 APK
- 领域层全部纯函数 + 单元测试：
  - WeekCalculator：学期起始日→当前教学周；单双周；自定义周次列表匹配
  - CourseStatusResolver：未开始/进行中/已结束
  - ReminderPlanner：给定课程集合与当前时刻→未来提醒触发时刻列表（过滤无效周次、已过期、停课日）
- 验收：`gradlew :app:testDebugUnitTest` 真实跑绿 + assembleDebug 真实出包

### 批次 2：数据层 + 课程管理 UI
- Room 实体/DAO/数据库 + DataStore 设置
- 周课表网格页（周切换）、课程详情编辑页（增删改、周次编辑、颜色）、设置页（学期起始日、总周数、作息时间、默认提醒）
- 验收：DAO 插入/查询测试 + 手动跑 App 截图周课表

### 批次 3：图片导入链路
- 相册选图（PhotoPicker）→ ScheduleRecognizer 云端识别 → 识别进度/失败提示 → 导入确认页（可编辑表格、低置信度标黄、冲突提示）→ 确认入库
- 节次模式：识别出的「第 X-Y 节」按 PeriodTime 映射为时间
- 验收：用真实课表截图跑通识别→确认→入库全流程

### 批次 4：小组件 + 提醒
- Glance 2×2「下一节课」（课程名/时间/地点/倒计时或空闲态）
- Glance 4×2「今日课程」（日期、按时间排列、区分状态、下一节高亮）
- 提醒调度全链路 + 通知权限引导 + 课程变更后重排
- 验收：模拟器/真机添加小组件，改课程后小组件与提醒同步变化

### 批次 5：集成验收 + 交付
- PRD 八条 MVP 验收标准逐条核对
- 出 release APK（交付形态 = 可直接安装的 APK 文件放到项目根目录，附安装说明）
- cc-kotlin-reviewer 走查 + 修复

## 四、派单与角色

- **执行者：** `cc-tars`（通用写权限 Read/Write/Edit/Bash/Grep/Glob，非 Java 项目惯例）
- **走查：** `cc-kotlin-reviewer`（只读）——批次 5 使用，stdout 由总控落盘
- **并发：** 批内串行为主（Gradle/Android 工程文件耦合高），批次 1 的三个领域类可拆 2 路并行
- **验收铁律：** 每批总控实际跑 `gradlew testDebugUnitTest` / `assembleDebug`，不采信自报

## 五、风险

| 风险 | 对策 |
|---|---|
| 本机无 Android 构建环境 | 批次 0 专门处理；SDK 下载走国内镜像 |
| 无真机时小组件/提醒只能模拟器验证 | 用 emulator 验证；用户有 Android 真机则侧载 APK 实测 |
| 视觉识别 API 需 key | 设置页自填 key（复用用户现有 DeepSeek/其他兼容接口），识别失败有明确提示 |
| AlarmManager 精度受国产 ROM 限制 | 文档注明白名单设置引导；WorkManager 兜底 |
